# 本地独立电商 ERP

根据导师演示 ERP 的公开前端和接口规则开发的本地版本。前端保持原有模块、列表、单据详情和表单结构；后端、数据库、示例业务数据由本项目独立实现，运行时不连接导师服务器。

## 启动

需要 Python 3.11 或更新版本，无第三方 Python 依赖。在本目录运行：

```powershell
python run.py
```

访问 http://127.0.0.1:5186/lingxing-erp/ ，账号和密码均为 `admin`。默认只监听本机地址，用于课程演示和后续开发，不是已经完成生产部署的系统。

首次启动自动建立 `data/erp.sqlite3` 并初始化示例数据；再次启动不会重置已有记录。更换端口或创建另一套独立数据库：

```powershell
python run.py --port 5187 --db data/second-demo.sqlite3
```

关闭启动进程即可停止服务。备份数据库时先停止服务，再复制整个 `data` 目录（包含可能存在的SQLite WAL文件）；恢复时也先停止服务，保留当前数据库副本。

## 当前实现

| 范围 | 可用行为 |
| --- | --- |
| 页面结构 | 13个模块、123个菜单入口，保留原站的复用视图设计 |
| 基础资料 | 产品、供应商、仓库、Listing、员工、店铺等新增/查询/编辑；业务关联限制删除 |
| 通用操作 | 搜索、筛选、分页、列管理、详情、关联单据、前端CSV导入导出 |
| 采购 | 补货建议生成采购、提交审批、审核、确认下单、创建收货单、逐SKU质检、显式库存入库 |
| 采购付款 | 凭证登记、精确幂等、超付与币种校验、付款补偿、结束剩余到货 |
| 采购变更 | 原值对比、提交、审核、应用及来源版本失效检查 |
| 销售 | 原币全额收款登记、分批发货、库存扣减、冻结、解冻、未收款取消 |
| 退货 | 按已发货数量授权、退款额度控制、良品/次品入库、本地负数退款凭证 |
| FBA | 计划审批、库存预留/释放、配货、发运扣库存、逐SKU分批签收 |
| 库存 | 入出库确认、逐单事务、批量部分失败、库存流水、调拨在途与整单接收、受限补偿冲销 |
| 盘点 | 仓库快照、良品/次品实盘、审批、差异过账、版本冲突和未发生后续变动的补偿 |
| 财务与统计 | 经营首页、销售/广告报表、已发货贡献利润、应收应付、库龄、物流费用 |

这些是本地业务能力，付款/退款表示凭证登记。店铺和物流资料不代表实际平台授权或真实物流推送。

## 与原站的差异和当前边界

- 本项目不是导师后端源码的恢复，也不是完整复现253个原接口的生产系统。原始兼容平台路径和管理员仓库快照导出未接入；本地接口文档已排除这些路径。相同路径的参数细节仍可能存在差异。
- 菜单中的57个复用视图沿用原站设计：例如1688、委外、AI文案等标题不表示已经集成外部服务。
- 采购普通收货后必须逐SKU质检，再显式确认入库。供应商预检/免检的自动分流和复杂异常收货规则尚未做到与原版逐项一致。
- 本地盘点从创建草稿就锁定仓库，严于原站的草稿/提交分阶段行为。
- 库存补偿目前要求相关批次没有后续流水或余额变化，不提供复杂依赖链的自动逆序冲销。
- 利润报表仅计算本地已发货数量、记录的原币净金额和商品成本，不包含真实平台费、广告分摊、头程分摊和管理费用。多币种准确结算及历史成本变动还需要完善。
- 店铺/仓库范围已有服务端校验和分页前过滤。缺少可可靠归属范围的资料对受限账号会返回空结果或拒绝；扩展模块的细粒度权限仍应继续逐项验收。
- 暂无生产登录限流、HTTPS部署、任务队列、定时备份、数据库迁移框架、多租户、真实平台集成和完整性能验收。
- 人工测试中心沿用参考操作指导，勾选不代表自动验收成功；自动验证结果看下列测试命令和证据。

## 修改入口

- `frontend/index.html`、`frontend/static/style.css`：页面框架和样式。
- `frontend/static/nova-theme.css`、`nova-theme.js`：NOVA 新主题、侧栏和经营概览展示；最后加载，保留原业务入口与数据请求。
- `frontend/static/app.js`：菜单、页面配置、通用列表与表单。
- `frontend/static/*workflow.js`：业务界面。
- `erp/api.py`：接口分发、校验、权限、通用维护。
- `erp/store.py`：SQLite数据访问、账号、会话和幂等。
- `erp/commerce.py`：采购、销售及FBA。
- `erp/stock.py`：库存、流水、调拨、盘点。
- `erp/changes.py`：退货、采购变更和付款补偿。
- `erp/views.py`、`erp/extensions.py`：统计与版本化资料。
- `erp/seed.py`：新数据库的独立示例数据。

业务资源使用SQLite表中的JSON记录保存，便于课程阶段扩展字段；关键动作在事务中更新单据、库存和流水。后续可将数据访问层迁移到关系更明确的表结构和其他数据库。

`tools/build_frontend.py` 只在文件不存在时从参考快照初始化前端，保留你之后对前端的修改；它每次会重新生成 `frontend/openapi.yaml`，所以不要直接在这个生成文件里维护自定义接口说明。

## 验证

```powershell
python -m unittest discover -s tests -v
```

24项自动测试已通过，覆盖库存不足整笔回滚、并发幂等、分批销售、采购质检入库、退款、FBA、盘点、权限范围、付款补偿、变更失效、发票版本、报价历史和保存回读。

前端核心页面另外通过浏览器检查。REA浏览器验证需要Edge和Node/npm（本次使用REA 6.4.0）：

```powershell
python tools/rea_browser_check.py
```

先启动ERP。工具使用临时无界面浏览器和本地默认测试账号，场景JSON仅存环境变量引用，不记录密码或令牌；证据、结果和首页截图保存在 `analysis/local-verification/`。
